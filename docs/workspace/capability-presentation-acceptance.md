# Provider-neutral Workspace capability presentation

## Implementation
The chat picker and agent builder use customer-safe TuGPT labels, not backend model labels/descriptions. Private/hosted model badges and the private-model chat header are removed. A single legacy configured route is presented as TuGPT Assistant; Standard/Advanced/Fast are supported only when explicitly supplied as experience metadata. Multiple legacy routes without that metadata are not offered. No frontend mapping from provider/model identity to tiers is invented. Explicitly unavailable entries cannot be selected, and unavailable saved choices never silently fall back. Agent identity, including unavailable/loading identity and screen-reader status, is preserved.

The Workspace server-rendered pages strip legacy labels/descriptions before passing model presentation data to the client. Chat request errors no longer echo arbitrary server text, and network error messages do not echo transport exceptions. Raw legacy keys still exist in API payloads and option values: this is presentation hardening, NOT full network-level provider confidentiality. Backend opaque IDs are required before the latter can be accepted. Generated answer content and approved-tool server messages also need backend policy/error-contract review; no arbitrary redaction of customer documents or assistant answers was added.

- Main flow: 67 assertions at each of 360/390/768/1440 px, including normal chat, TuGPT capability selection, collection creation/upload/indexing, agent/model binding, cited chat, continuation, reopen/refresh and branding absence on the final chat surface.
- Lifecycle: 12 assertions at each width, including agent editing, unlink/relink, conversation search/rename/archive/restore/delete and explicit rejected-draft retry.
- File/recovery: 48 assertions across four widths; second-user private-file denial and non-replaying reconciliation included.
- Permission/search: 13 assertions, including second-user agent/conversation denial and role-aware controls.

Actual APIs, database authorization, file storage, keyword indexing and citation persistence are used in the disposable environment. Answers are generated by the existing deterministic simulated model and visibly labeled as such. Sessions are pre-existing synthetic sessions, not verified external SSO. There is only one configured browser capability; Standard/Advanced/Fast routing is NOT demonstrated against real models.

## Reproduction

For each width 360, 390, 768, 1440, create the evidence subdirectory, set WIDTH and EVIDENCE_DIR, and run in order:

```sh
node scripts/workspace-demo/capability-browser.cjs
node scripts/workspace-demo/capability-lifecycle.cjs
```

Using the 1440 evidence directory, run capability-permissions.cjs and capability-files-recovery.cjs. Lifecycle deletes only its normal test conversation; rerun browser before repeating lifecycle. Files/recovery deletes only newly created test files. Permissions temporarily changes disposable fixture roles and restores the original agent role. No secrets are included in this package.
